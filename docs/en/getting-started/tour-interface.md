# Desktop interface tour

The desktop app organizes file work into separate views. Choose the workspace first so that files, tasks and visualizations refer to the same context.

| View | Purpose |
| --- | --- |
| Local / cloud workspace | Choose the runtime context available to your account; select task inputs, compose a request and inspect its results. |
| Files | Import files and inspect names, sizes, types and available preview actions. |
| Tasks | Review processing work and generated outputs. |
| Templates | Choose configured task templates. |
| Graph | Switch between task relationships and data analysis. |
| File Galaxy | Explore the workspace's visual file map and connections. |
| Settings | Configure providers, runtimes and other application settings. |

## Importing and selecting are separate

Files is the catalog for imported material and its preview actions. Create processing requests in the workspace: confirm the selected inputs, choose a feature or write a prompt, and check the model/services before using the submit arrow. The workspace may use two or three columns, so panel positions can differ. See [the first task steps](./index.md#run-the-first-task).

## Read the graph modes separately

Task relationships show connections involving processing work and files. Data analysis explores structured graph data. A node in one view is not a promise that the same kind of information is available in every other view.

If a view is empty, check the selected workspace and whether relevant files or results exist. Example data is for learning the interface; it is not evidence that a task has processed your own files. Use a small real file you can verify for your first result.

See [your first graph inspection](./first-visualization.md).
